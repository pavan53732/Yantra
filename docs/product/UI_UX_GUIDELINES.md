# UI and UX Guidelines

## Direction

Yantra should not look like a traditional IDE and should not behave like a chat application. The product direction should be closer to Lovable, Linear, Raycast, Arc Browser, Vercel Dashboard, and Notion's layout philosophy than to docking-heavy development environments.[cite:18]

## Experience goals

- Extremely clean.
- Almost no visual noise.
- Large spacing.
- Subtle animations.
- Dark-first.
- Typography-first.
- Cards instead of panels where appropriate.
- Mission-oriented interface.[cite:18]

## Interaction rule

The editor is a tool, not the product. The product is the engineering workflow.[cite:18]

## Anti-direction

Avoid taking core UI inspiration from Eclipse, IntelliJ, Visual Studio, and dense JetBrains-style docking systems because they expose too much complexity and conflict with the intended minimal product experience.[cite:18]
