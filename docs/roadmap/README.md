# Roadmap

Yantra's roadmap is organized into sequential phases. Electron and the Desktop UI deliberately do not appear until Phase 4 — the engine is designed and built before any UI framework decision constrains it. Between Research and full Architecture/Core Engine work sits **Phase 0.5 — Engineering Specification Freeze**, which must be reviewed and approved before production code lands in any package.

## Phases

1. [Phase 0 — Research](./phase-0-research.md)
2. [Phase 0.5 — Engineering Specification Freeze](./PHASE_0_5_SPECIFICATION_FREEZE.md) — drafting complete, pending review
3. [Phase 1 — Product Definition](./phase-1-product-definition.md)
4. [Phase 2 — Architecture](./phase-2-architecture.md)
5. [Phase 3 — Core Engine](./phase-3-core-engine.md)
6. [Phase 4 — Desktop Application](./phase-4-desktop-application.md)

## Milestones

Phase 0.5 tracks its own milestone checklist in
[`PHASE_0_5_SPECIFICATION_FREEZE.md`](./PHASE_0_5_SPECIFICATION_FREEZE.md) —
all ten specification priorities (schemas, protocols, state machines,
contracts, provider interface, Mission DSL, knowledge graph, observability,
verification framework, decision policy) are drafted. Formal review/approval
is the remaining gate before implementation begins.
